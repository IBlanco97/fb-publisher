02 · Modelo de datos

Qué es exactamente "una cuenta" aquí

El sistema no guarda el usuario y contraseña de Facebook en una base de datos. Guarda un nombre y un proxy — la sesión iniciada vive aparte, como el navegador la dejó.

Se guarda

En la base de datos

  • Nombre de la cuenta
  • Datos del proxy asignado
  • Si está activa o pausada
  • Grupos, plantillas y reglas de horario
No se guarda ahí

Vive en el navegador

  • Usuario y contraseña de Facebook
  • La sesión iniciada (cookies)
  • Queda en una carpeta en disco por cuenta
  • Si se borra esa carpeta, hay que loguear de nuevo
03 · Primer contacto

Cómo se conecta una cuenta por primera vez

Conectar una cuenta nueva requiere que una persona la loguee a mano una vez. Después, la máquina publica sola con esa sesión.

1
Se pulsa "Iniciar sesión" en el panel

Junto al nombre de la cuenta que aún no tiene sesión activa.

2
Se abre una ventana de navegador visible

No es invisible: aparece una ventana de Chrome real, para poder escribir usuario, contraseña y resolver 2FA o verificaciones.

3
La persona completa el login a mano

Como si entrara a Facebook desde su propio navegador — porque, técnicamente, es exactamente eso.

4
La sesión queda guardada en disco

Desde ese momento, esa cuenta publica sola, sin volver a pedir login, hasta que Facebook la cierre por su cuenta.

El punto importante: esa ventana de navegador se abre en la máquina donde vive el sistema — no en la computadora de quien mira el panel. Si el sistema corre en un servidor remoto sin pantalla, ese paso 2 necesita una forma de ver esa ventana (escritorio remoto), o resolverse de otra manera antes de mudarlo.
04 · Red

Proxy: uno por cuenta, opcional pero recomendado

Cada cuenta puede tener su propio proxy asignado. Si no lo tiene, sale a internet con la IP de la máquina donde corre el sistema.

EscenarioIP con la que publicaRiesgo
Cuenta con proxy propioLa del proxy asignadoBajo — se comporta como una persona distinta
Cuenta sin proxyLa del servidorSube si hay varias cuentas así
Varias cuentas, misma IPCompartida entre todasAlto — Facebook puede vincularlas entre sí
Regla práctica: cuantas más cuentas activas publiquen a la vez, más proxies distintos hacen falta — idealmente uno por cuenta. Es la variable clave para calcular cuántos proxies comprar además de los ya disponibles.
05 · Contenido

Qué publica cada cuenta, y cuándo

Cada cuenta tiene sus propias reglas: en qué grupos publica, con qué plantillas, y con qué horario. No hay una regla global compartida entre todas.

07 · Mudanza

Qué hace falta para pasarlo a un servidor

Técnicamente es viable. Estas son las piezas que hay que resolver antes, no después.

Conservar la carpeta de datos entre reinicios

Ahí vive la base de datos y las sesiones ya logueadas de cada cuenta. Si se pierde esa carpeta, se pierden ambas cosas.

Resolver el login remoto

El primer login de cada cuenta nueva necesita ver una ventana de navegador. En un servidor sin pantalla hace falta escritorio remoto, o cambiar ese paso.

Proxy por cada cuenta activa

Definir cuántas cuentas van a publicar en simultáneo, para saber cuántos proxies adicionales comprar.

Decidir quién más va a entrar al panel

Hoy no hay login de operador ni permisos por persona — cualquiera con la dirección del panel ve y controla todo.

08 · Sobre la mesa

Lo que falta decidir

No son preguntas técnicas — son de negocio. La respuesta a cada una cambia cómo se arma el despliegue.

¿Cuántas cuentas de Facebook van a publicar en total?
Define cuántos proxies hacen falta y qué tan grande debe ser el servidor.
¿Local o en un servidor propio?
Local es más simple hoy; servidor permite que corra sin depender de una computadora encendida.
¿Va a operarlo una sola persona o varias?
Hoy el sistema asume un solo operador — soportar varios con permisos distintos es trabajo adicional.
¿Con qué frecuencia se conectan cuentas nuevas?
Cada cuenta nueva necesita ese login manual una vez — importa si es algo raro o algo constante.
